# 📤 上传博客（Obsidian → 站点）

一句话流程：**Obsidian 写好笔记 → 右键 Upload → 自动推到 GitHub → 自动部署上线**。

---

## 0. 一次上传要填的属性

在笔记最前面（front-matter）写好这些属性，**建议用 Obsidian 属性面板加**：

| 属性 | 类型 | 填什么 | 作用 |
|---|---|---|---|
| `share` | 复选框 | ☑ 勾上 | 发布开关（必须 `true` 才会上传） |
| `target` | 文本 | `blog/posts` | 放哪个文件夹 |
| `date` | 日期 | `2026-02-20` | 文章日期（必填，博客排序用） |
| `categories` | **列表** | `随笔` / `CTF` | 文章分类（**必须是列表**） |
| `comments` | 复选框 | ☑ 勾上 | 开启评论 |
| `title` | 文本 | `我的文章` | 标题 / 文件名 |

**最容易踩的 3 个坑：**
- `categories` 一定选 **列表**（⛓），选成文本会变成字符串、部署失败
- `share` / `comments` 一定选 **复选框**（☑）
- `target` 只写文件夹，**别把文章名写进去**（文件名用 `title`）

---

## 1. 博客文章完整模板（复制用）

```yaml
---
share: true
target: blog/posts
date: 2026-02-20
categories:
  - 随笔
comments: true
title: 我的文章
---
这是文章开头（会显示在博客首页卡片）

<!-- more -->

后面是正文、图片等（只在文章详情页显示）
```

> 图片在首页卡片上**自动隐藏**（前端样式处理），`<!-- more -->` 只控制卡片字数，**可加可不加**。

---

## 2. 属性类型怎么设（Obsidian 属性面板）

右键每个属性 → 属性类型：

| 属性 | 选 | 得到 |
|---|---|---|
| `share` | 复选框 | `share: true` |
| `comments` | 复选框 | `comments: true` |
| `target` | 文本 | `target: blog/posts` |
| `date` | 日期 | `date: 2026-02-20` |
| `categories` | **列表** | `categories:` 下缩进 `- 随笔` |
| `title` | 文本 | `title: 我的文章` |

设完**切到源码模式**核对一遍，`categories` 下面必须是缩进的 `- 随笔`。

---

## 3. 属性详解

### `share`（发布开关）
- `true` → 会被 Enveloppe 推送到仓库
- 不写或 `false` → 不会发布
- **不想发的笔记千万别写 `share: true`**

### `target`（路由到哪个目录）
决定放哪个**目录**；`title` 决定**文件名**。详见第 4 节。

### `date`（必填）
Material 博客插件按日期归档/排序，**不能省**。格式 `YYYY-MM-DD`。

### `categories`（分类，列表）
博客插件按分类筛选。可以多个：

```yaml
categories:
  - 随笔
  - CTF
```

### `comments`（评论）
`true` 开启 giscus 评论（站点已装好，勾上即生效）。

### `title`（标题/文件名）
作为页面标题和发布后的文件名。可选（默认用笔记文件名）。

---

## 4. target 路线（放到哪个区）

| `target` | 落盘位置 | 站点表现 |
|---|---|---|
| `blog/posts` | `docs/blog/posts/<title>.md` | 博客文章，自动上博客列表 |
| `blog/posts/随笔` | `docs/blog/posts/随笔/<title>.md` | 博客文章，放子目录（仍自动上博客） |
| `notes/crypto` | `docs/notes/crypto.md` | 学习笔记，自动进导航 |

> `target` = **文件夹**，`title` = **文件名**。别把文章名写进 `target`（否则多一层同名文件夹）。

---

## 5. 学习笔记自动导航

- `docs/notes/` 下的笔记**自动进导航**，不用改 `mkdocs.yml`
- `nav: false` → 隐藏，不进导航
- `title` → 导航显示名；`order: 1` → 排序（小在前）
- 子文件夹自动嵌套：`target: notes/crypto/rsa` → 「学习笔记 → crypto → rsa」

示例：

```yaml
---
share: true
target: notes/crypto/rsa
title: RSA 大数分解
order: 1
---
```

## 6. 图片

- 用 `!城堡到工业区的远眺.jpg` 嵌入
- `|别名`（`!名字`）是 alt 文本，**无害**
- 图片自动放进 `docs/assets/images/`（Enveloppe 附件目录已配好，不用动）
- **博客卡片上的图片会自动隐藏**，你只管正常写

## 7. Obsidian 彩色框(Callout)

Obsidian 里的彩色框写法会在**构建时自动转成站点的彩色框(admonition)**，直接在笔记里写就行：

```markdown
> [!NOTE] 绿色提示
> 内容

> [!INFO] 蓝色信息
> 内容

> [!WARNING] 黄色警告
> 内容

> [!DANGER] 红色危险
> 内容

> [!SUCCESS] 绿色成功
> 内容
```

- **绿**：NOTE / TIP / SUCCESS　**蓝**：INFO / QUESTION / EXAMPLE
- **黄**：WARNING　**红**：DANGER　**紫**：BUG　**灰**：QUOTE
- 嵌套：用 `> > [!TYPE]` 变成内层框
- 代码块里的 `> [!NOTE]` 不会被误转

### 其他行内语法（站点直接支持，和 Obsidian 显示一致）

| Obsidian 写法 | 站点效果 |
|---|---|
| `~~删除线~~` | 删除线（前后贴字也能渲染） |
| `==高亮==` | 高亮标记（前后贴字也能渲染） |
| `%%注释%%` | 页面上不显示（只在 Obsidian 编辑视图可见） |

> 删除线 / 高亮由构建钩子 `scripts/obsidian_inline.py` 全局转换，代码块里写了原样保留、不会被误转。

## 8. Obsidian 内部链接(wikilink)

Obsidian 的 <code>&#91;&#91;笔记&#93;&#93;</code> 内部链接在站点上会**自动转成可点击链接**(roamlinks 插件处理)：

- <code>&#91;&#91;笔记名&#93;&#93;</code> — 链接到笔记
- <code>&#91;&#91;笔记名&#93;&#93;|显示的文字</code> — 链接 + 自定义显示文字

- 目标笔记**存在** → 转成可点击链接
- 目标笔记**不存在** → 转成纯文字(CI 构建前自动兜底,不会让部署失败)
- 别用 <code>&#91;&#91;笔记#中文标题&#93;&#93;</code> :中文标题锚点是数字 id,跳不过去,只链到笔记本身就好

## 9. 上传操作

1. 写完笔记、front-matter 填好
2. （可选）Enveloppe → **Test mode** 先预览模拟路径
3. 命令面板 `Ctrl+P` → 搜 `enveloppe` / `upload`：
   - **Upload single current active note**：只传当前这篇（最常用）
   - **Upload all notes**：传所有 `share: true` 的
4. 等约 1-2 分钟，刷新 `https://bishouyou.github.io/bishou-blog/` 查看

### Enveloppe 全部命令速查

| 命令 | 作用 |
|---|---|
| **Upload single current active note** | 推送当前打开的这篇（最常用） |
| **Upload all notes** | 推送所有 `share: true` 的笔记（一键全发） |
| **Upload unpublished notes** | 只推还没发布过的 |
| **Refresh all published notes** | 重新推送所有（改版后全量同步） |
| **Test the connection** | 测试 GitHub 连接（代理是否生效） |
| **Check the rate limit** | 查 GitHub API 限额 |

---

## 10. 网络 / 代理提示

- Enveloppe 走 GitHub API，需配一个**全局代理**（Obsidian 插件 `Global Proxy`）
- 代理类型：socks 优先，http/https 兜底（本机端口见代理客户端设置）
- 代理若不通，用 Enveloppe 的「Test connection」排查
- GitHub token：勾 **`repo`** 作用域即可，**不用** `workflow`

---

## 11. 上传失败常见原因速查

| 现象 | 原因 | 解决 |
|---|---|---|
| 部署失败：categories 期望列表 | `categories` 是文本/字符串 | 属性类型改 **列表** |
| `share: "true"` 带引号 | `share` 是文本 | 属性类型改 **复选框** |
| 生成 `blog/posts/文章名/文章名.md` | `target` 写了文章名 | `target` 只写 `blog/posts` |
| 笔记没出现在导航 | 是 notes 且写了 `nav: false` | 去掉 `nav: false` |
| 连接超时 / 401 | 代理不通或 token 失效 | 见第 10 节代理提示，重签 PAT（`repo` 作用域） |
